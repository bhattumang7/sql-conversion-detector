SilentScan

A static analyser for SQL Server (T-SQL) code.

SilentScan finds correctness and performance problems that are detectable from SQL code and schema alone — before the query ever runs in production. It is type-aware, direction-aware, and lineage-aware: findings trace a predicate back through views and table-valued functions to the base table column that actually causes the problem.

What it looks for

  • Implicit conversions that silently turn an index seek into a scan
  • Collation mismatches across joined or compared columns
  • Non-sargable predicates (function-wrapped columns, leading-wildcard LIKE, column arithmetic)
  • Dynamic SQL whose text can be proven constant, analyzed the same way as static SQL

Those are examples. The complete catalogue — every rule, with what it reports and how to fix it — is in the rule reference.

How it's verified

Every verdict-bearing rule is checked against a plan-XML oracle, not inferred from plan shape or table size — a finding is confirmed only when the execution plan actually shows the conversion happening on the column side of the predicate.

Usage

silentscan scan <path-to-sql>
silentscan scan-db <connection-string>   # read-only, SELECT-only
silentscan scan-corpus <manifest.json>
silentscan verify-corpus <manifest.json>

Output is versioned JSON, with a SARIF export for CI.
