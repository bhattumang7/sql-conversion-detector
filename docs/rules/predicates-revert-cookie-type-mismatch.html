Revert Cookie Type Mismatch

silentscan/predicates/revert-cookie-type-mismatch

A medium-confidence or low-confidence finding of this same rule links here too - only the finding's certainty differs, not the underlying issue.

Why is this an issue?

REVERT WITH COOKIE = @cookie references a variable whose declared type is not a fixed-length varbinary of at least 50 bytes - oracle-confirmed (Msg 15533, "Invalid data type is supplied in the 'Revert' statement") the engine rejects any narrower fixed length (varbinary(49) and below), a MAX length, or a different type entirely, decidable purely from the variable's own DECLARE or parameter type. varbinary(100) is the conventional choice (and what EXECUTE AS ... WITH COOKIE INTO documentation shows), but it is not the only accepted width - oracle-confirmed varbinary(50) through at least varbinary(8000) all round-trip successfully, so this rule only flags what actually fails, not merely what differs from 100.

REVERT WITH COOKIE = @cookie exists to undo an EXECUTE AS ... WITH COOKIE INTO @cookie impersonation, and the engine requires the cookie variable to be a fixed-length varbinary of at least 50 bytes - not a narrower fixed length, and not varbinary(max). Oracle-confirmed against a real engine: declaring the cookie variable as varbinary(10) and passing it to REVERT WITH COOKIE fails to compile with Msg 15533 ("Invalid data type is supplied in the 'Revert' statement"), even though varbinary(10) is a perfectly ordinary, otherwise-legal declaration - and the failure threshold is exact: varbinary(49) still fails, varbinary(50) succeeds. varbinary(100) is the width Microsoft's own EXECUTE AS documentation shows and the conventional choice, but it is not a hard requirement - oracle-confirmed varbinary(50) through at least varbinary(8000) all round-trip successfully through EXECUTE AS ... WITH COOKIE INTO and REVERT WITH COOKIE. A different type entirely, a narrower fixed length, or a MAX length is rejected the same way (Msg 15533), and the declared type is knowable purely from the variable's own DECLARE or parameter definition, with no catalog or runtime data needed.

How can I fix it?

Declare the cookie variable as a fixed-length varbinary of at least 50 bytes - varbinary(100) is the conventional choice - and never varbinary(max) or a narrower fixed length.

A cookie variable declared narrower than the 50-byte minimum never compiles

Noncompliant code example

DECLARE @cookie varbinary(10);
EXECUTE AS USER = 'dbo' WITH COOKIE INTO @cookie;
REVERT WITH COOKIE = @cookie;

Fails to compile with Msg 15533 ("Invalid data type is supplied in the 'Revert' statement") - REVERT rejects any fixed varbinary length under 50 bytes.

Compliant solution

DECLARE @cookie varbinary(100);
EXECUTE AS USER = 'dbo' WITH COOKIE INTO @cookie;
REVERT WITH COOKIE = @cookie;

varbinary(100) is a fixed length at or above the 50-byte minimum the engine actually requires.
