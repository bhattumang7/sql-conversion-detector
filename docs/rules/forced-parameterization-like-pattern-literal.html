LIKE Pattern Literal

silentscan/forced-parameterization/like-pattern-literal

A medium-confidence or low-confidence finding of this same rule links here too - only the finding's certainty differs, not the underlying issue.

Why is this an issue?

A LIKE predicate's pattern is a literal, not a variable - the engine leaves it unparameterized even under PARAMETERIZATION FORCED, so a workload varying only this pattern still recompiles per distinct value.

Reported only when the target database has `PARAMETERIZATION FORCED` on - a deliberate setting meant to stop per-literal ad-hoc plan-cache bloat by having the engine treat every literal in a query as if it were a parameter, sharing one compiled plan across calls that only differ by value.

Confirmed directly against a real engine: under `PARAMETERIZATION FORCED`, `WHERE Id = 42 AND Name LIKE 'abc%'` compiles to a shared `(@0 int) ... WHERE Id = @0 AND Name LIKE 'abc%'` plan - the equality parameterizes, the LIKE pattern does not. This is a real, documented exception, not a bug in the engine - but it means a search query varying only its LIKE pattern (the overwhelmingly common real-world shape for a search box) gets a fresh compile per distinct pattern regardless of the setting, right where the setting was expected to help most.

How can I fix it?

Pass the LIKE pattern as a parameter or local variable instead of a literal - the engine has no exclusion for a LIKE predicate whose pattern is already a parameter.

A LIKE pattern hard-coded as a literal

Noncompliant code example

SELECT CustomerId, Name FROM dbo.Customers WHERE Name LIKE 'Smith%';

Under PARAMETERIZATION FORCED, the pattern stays literal in the cached plan - a search for 'Jones%' next recompiles instead of reusing this plan.

Compliant solution

CREATE PROCEDURE dbo.SearchCustomersByName @Pattern varchar(100) AS
SELECT CustomerId, Name FROM dbo.Customers WHERE Name LIKE @Pattern;

The pattern is already a parameter, so there is nothing for this exclusion to apply to - every call shares the one compiled plan regardless of PARAMETERIZATION FORCED.
