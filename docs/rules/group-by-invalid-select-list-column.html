Invalid Select List Column

silentscan/group-by/invalid-select-list-column

A medium-confidence or low-confidence finding of this same rule links here too - only the finding's certainty differs, not the underlying issue.

Why is this an issue?

A plain GROUP BY's select-list expression references a column that is neither an aggregate function argument nor shape-identical to a GROUP BY expression - oracle-confirmed (Msg 8120, "Column ... is invalid in the select list because it is not contained in either an aggregate function or the GROUP BY clause") this never compiles, decidable purely from the statement's own GROUP BY and select-list expressions. SQL Server has no functional-dependency-on-primary-key exception (unlike some other engines) - grouping by a table's full primary key does not exempt its other columns.

Once a `SELECT` has a plain `GROUP BY` clause, every select-list expression must either be an aggregate function call, or shape-identical to one of the `GROUP BY` expressions - SQL Server's binder rejects anything else at compile time, before any row is ever touched.

Oracle-confirmed (Msg 8120, "Column '...' is invalid in the select list because it is not contained in either an aggregate function or the GROUP BY clause") - this fails unconditionally, decidable purely from the statement's own `GROUP BY` and select-list expressions. Unlike some other database engines, SQL Server has no functional-dependency-on-primary-key exception: grouping by a table's full primary key does not exempt that table's other columns from this restriction.

Scoped to a plain `GROUP BY` (no `ROLLUP`/`CUBE`/`GROUPING SETS`, whose validity rules differ) - within that scope, a `GROUP BY` expression is matched to a select-list expression by structural shape (`GROUP BY Id + 1` covers `SELECT Id + 1`, but not `SELECT Id + 2`), matching the engine's own binding behavior exactly.

How can I fix it?

Add the column to the GROUP BY clause, or wrap it in an aggregate function.

Select-list column outside GROUP BY and outside an aggregate

Noncompliant code example

SELECT Id, Category, SUM(Amount) FROM dbo.Sale GROUP BY Category;

Id is neither in the GROUP BY clause nor inside an aggregate function - this statement fails to compile with Msg 8120 every time it runs, even if Id is the table's primary key.
