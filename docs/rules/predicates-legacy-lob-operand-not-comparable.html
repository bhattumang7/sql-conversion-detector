Legacy Lob Operand Not Comparable

silentscan/predicates/legacy-lob-operand-not-comparable

A medium-confidence or low-confidence finding of this same rule links here too - only the finding's certainty differs, not the underlying issue.

Why is this an issue?

A TEXT/NTEXT/IMAGE column is used in a comparison, IN list, BETWEEN, NULLIF, ORDER BY, GROUP BY, or a window function's PARTITION BY - oracle-confirmed the statement never compiles (Msg 306/402/421/249 depending on the shape): these legacy large-object types cannot be compared or sorted, except IS NULL or LIKE.

TEXT, NTEXT, and IMAGE - the pre-VARCHAR(MAX)/NVARCHAR(MAX)/VARBINARY(MAX) large-object types, deprecated but still present in older schemas - carry their own comparability restriction, distinct from (and stricter than) the ordinary type-precedence rules every other type follows. Confirmed directly against a real SQL Server instance: a TEXT/NTEXT/ IMAGE column used in =, &lt;&gt;, a range operator, an IN list, BETWEEN, or NULLIF fails to compile with Msg 402 ("The data types ... are incompatible in the ... operator"); referenced in ORDER BY, GROUP BY, or a window function's own PARTITION BY clause it instead raises Msg 306 ("The text, ntext, and image data types cannot be compared or sorted, except when using IS NULL or LIKE operator") - the engine's own error text names the two exceptions explicitly, and both were confirmed to actually compile: LIKE against a TEXT/NTEXT column works, and so does IS NULL. SELECT DISTINCT over one of these columns fails its own way (Msg 421), the identical restriction xml carries.

How can I fix it?

Migrate the column to VARCHAR(MAX)/NVARCHAR(MAX)/VARBINARY(MAX) - the modern large-object types support ordinary comparison, ordering, and grouping with none of this restriction. Where migrating isn't immediately possible, remove the column from the comparison/ ordering/grouping/DISTINCT position, or rewrite the comparison as a LIKE pattern instead.

Sorting by a TEXT column never compiles

Noncompliant code example

CREATE TABLE dbo.Article
(
    ArticleId INT NOT NULL PRIMARY KEY,
    Body      TEXT NOT NULL
);

SELECT ArticleId
FROM dbo.Article
ORDER BY Body;

Body is TEXT - this statement fails to compile with Msg 306 every time it runs.

Compliant solution

ALTER TABLE dbo.Article ALTER COLUMN Body VARCHAR(MAX) NOT NULL;

SELECT ArticleId
FROM dbo.Article
ORDER BY Body;

Body is migrated to VARCHAR(MAX) - the modern large-object type has no comparison/ordering restriction.
