Vector Function Non Vector Operand

silentscan/predicates/vector-function-non-vector-operand

A medium-confidence or low-confidence finding of this same rule links here too - only the finding's certainty differs, not the underlying issue.

Why is this an issue?

A VECTOR_DISTANCE/VECTOR_NORM/VECTORPROPERTY call's vector-position argument statically resolves to a non-vector type (any declared local variable, parameter, catalog column, CAST/CONVERT target, or literal) - oracle-confirmed (Msg 8116, "Argument data type ... is invalid for argument ... function") the statement never compiles, regardless of whether the value could otherwise convert from a vector-literal string.

VECTOR_DISTANCE, VECTOR_NORM, and VECTORPROPERTY - SQL Server 2025's native vector functions - require an actual VECTOR(n)-typed value at every vector-position argument. Confirmed directly against a real SQL Server 2025 instance: passing anything else there - a VARCHAR/NVARCHAR column or variable holding the vector's string representation, a VARCHAR(MAX)/NVARCHAR(MAX) value, a SQL_VARIANT, an XML value, or a bare string literal - fails to compile with Msg 8116 ("Argument data type ... is invalid for argument ... of ... function"). This is not limited to large-object types: even a short, ordinary VARCHAR(10) column fails identically. There is no implicit conversion from a vector-literal string into VECTOR(n) at these call sites; the value must already carry the VECTOR(n) type, typically via an explicit CAST(... AS VECTOR(n)).

A NULL literal or an expression whose type this pass cannot statically resolve is never flagged - only an argument whose declared type is provably not VECTOR is reported.

How can I fix it?

Pass an actual VECTOR(n)-typed value at this argument position - a column or variable declared VECTOR(n), or an explicit CAST(... AS VECTOR(n)) expression - instead of a string/other-typed value the engine would otherwise have to implicitly convert.

Passing a VARCHAR column to VECTOR_DISTANCE never compiles

Noncompliant code example

CREATE TABLE dbo.Embedding
(
    EmbeddingId INT NOT NULL PRIMARY KEY,
    RawVector   VARCHAR(4000) NOT NULL,
    Query       VECTOR(3) NOT NULL
);

SELECT EmbeddingId
FROM dbo.Embedding
WHERE VECTOR_DISTANCE('cosine', RawVector, Query) < 0.2;

RawVector is VARCHAR - this statement fails to compile with Msg 8116 every time it runs.

Compliant solution

SELECT EmbeddingId
FROM dbo.Embedding
WHERE VECTOR_DISTANCE('cosine', CAST(RawVector AS VECTOR(3)), Query) < 0.2;

RawVector is explicitly cast to VECTOR(3) before being passed - a genuinely VECTOR-typed argument.
