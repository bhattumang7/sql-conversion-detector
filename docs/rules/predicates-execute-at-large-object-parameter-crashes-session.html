Execute At Large Object Parameter Crashes Session

silentscan/predicates/execute-at-large-object-parameter-crashes-session

A medium-confidence or low-confidence finding of this same rule links here too - only the finding's certainty differs, not the underlying issue.

Why is this an issue?

An EXECUTE ('...', @param, ...) AT linked_server/data_source call passes a VARCHAR(MAX), NVARCHAR(MAX), or VARBINARY(MAX)-typed local variable or parameter as one of the remote call's arguments - oracle-confirmed (Docker, SQL Server 2022 and 2025) the connection is killed by an internal engine assertion failure ("pilb->m_cRef == 0", memilb.cpp) rather than returning a clean error, regardless of whether the remote call would otherwise have succeeded.

EXECUTE ( 'command_text', @param, ... ) AT linked_server (or AT DATA_SOURCE data_source_name, the elastic-query form) passes each additional comma-separated value as a remote-call parameter, independent of the command text itself. Confirmed directly against real SQL Server instances (2022 and 2025): passing a VARCHAR(MAX), NVARCHAR(MAX), or VARBINARY(MAX)-typed local variable or parameter at one of these positions does not produce a clean error - it crashes the connection outright with an internal engine assertion failure ("A system assertion check has failed", memilb.cpp, "pilb->m_cRef == 0") and kills the session. A same-length fixed-size parameter (e.g. NVARCHAR(100)) or an INT at the same position does not trigger this. The command text argument itself (the first string) is unaffected even when it is MAX-typed - only the additional parameter positions are.

How can I fix it?

Do not pass a MAX-typed variable or parameter as an EXECUTE (...) AT argument. Truncate it to a fixed-length type before the call, or restructure the remote call so the large value is embedded in the command text itself rather than passed as a separate parameter.

Passing an NVARCHAR(MAX) parameter to EXECUTE AT crashes the connection

Noncompliant code example

DECLARE @payload NVARCHAR(MAX) = N'...';
EXEC ('SELECT 1', @payload) AT MyLinkedServer;

@payload is NVARCHAR(MAX) - this crashes the connection with an internal assertion failure instead of a clean error.

Compliant solution

DECLARE @payload NVARCHAR(4000) = N'...';
EXEC ('SELECT 1', @payload) AT MyLinkedServer;

@payload is a fixed-length NVARCHAR(4000) - the remote call parameter binds normally.
