Online Rebuild Legacy Lob Alter Column

silentscan/catalog/online-rebuild-legacy-lob-alter-column

A medium-confidence or low-confidence finding of this same rule links here too - only the finding's certainty differs, not the underlying issue.

Why is this an issue?

An ALTER TABLE ... ALTER COLUMN ... WITH (ONLINE = ON) statement either currently has, or is converting the column into, a TEXT/NTEXT/IMAGE type - oracle-confirmed (Msg 11427, "The online ALTER COLUMN operation cannot be performed for table ... because column ... currently has or is getting altered into an unsupported datatype: text, ntext, image, CLR type or FILESTREAM") the statement never completes online for either direction of that conversion.

ALTER TABLE ... ALTER COLUMN ... WITH (ONLINE = ON) is rejected whenever the column either currently is, or is being converted into, TEXT/NTEXT/IMAGE - oracle-confirmed (Msg 11427, "The online ALTER COLUMN operation cannot be performed for table '...' because column '...' currently has or is getting altered into an unsupported datatype: text, ntext, image, CLR type or FILESTREAM") both directions of that conversion fail online, decidable purely from the column's own before/after catalog types.

How can I fix it?

Drop ONLINE = ON and run the ALTER COLUMN offline, or migrate the column to VARCHAR(MAX)/NVARCHAR(MAX)/VARBINARY(MAX) before altering it online.

Online ALTER COLUMN on an NTEXT column

Noncompliant code example

CREATE TABLE dbo.Article (ArticleId INT NOT NULL PRIMARY KEY, Body NTEXT NULL);
ALTER TABLE dbo.Article ALTER COLUMN Body NTEXT NULL WITH (ONLINE = ON);

dbo.Article.Body stays NTEXT across the ALTER, so the online operation fails with Msg 11427.

Compliant solution

CREATE TABLE dbo.Article (ArticleId INT NOT NULL PRIMARY KEY, Body NVARCHAR(MAX) NULL);
ALTER TABLE dbo.Article ALTER COLUMN Body NVARCHAR(200) NULL WITH (ONLINE = ON);

NVARCHAR(MAX) to NVARCHAR(200) never involves a legacy large-object type, so the online ALTER COLUMN succeeds.
